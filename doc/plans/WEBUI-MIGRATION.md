# Предложение: управление GPO в freeipa-webui

**Статус:** предложение, не описание текущей системы. Заменяет `INTEGRATION-PLAN.md` и `GPO-EDITOR-ANALYSIS.md`
(остаются в истории git). Сначала нужен инструментарий из [FRONTEND-DX-PLAN.md](FRONTEND-DX-PLAN.md).
Размеры и факты сверены с репозиторием 2026-10-18.

## 1. Что есть сейчас

| Слой | Состояние |
|---|---|
| Серверные команды | `gpo_*`, `chain_*` (включая `enable`/`disable`, `moveup_gpc`/`movedown_gpc`), `gpmaster_show`/`gpmaster_mod` (`add_chain`, `remove_chain`, `moveup_chain`, `movedown_chain`), около 30 команд `gpo_editor_*` |
| Страницы в штатном Web UI | `chain.js` (1193 строки) и `gpo.js` (395), jQuery-фасеты FreeIPA |
| Редактор GPUI | vanilla JS + AMD, около 20 тыс. строк, 22 layout'а preferences, targeting editor (~1650 строк, drag-and-drop с клавиатурной альтернативой), локали EN/RU, около 40 UI-тестов |
| Граница с libadmix | Только на сервере. Браузер видит типизированный RPC `gpo_editor_*` (`util/API.js`, ~29 методов) и не знает про SYSVOL |

Иерархия: GPMaster → Chain (упорядоченный) → GPO. При конфликте побеждает последняя политика.

## 2. Что предлагается

Три страницы в `freeipa-webui` (React + PatternFly + RTK Query): список/детали GPO, цепочки с приоритетами и
enable/disable, GPMaster (порядок цепочек, PDC Emulator). Редактор GPUI подключается как есть. Серверная часть не меняется.

Режимы сосуществования с текущим UI: временный двойной UI, затем замена (рекомендуется); iframe-прокси отвергнут как сложный.

## 3. Объём и оценка

Рабочие дни, один разработчик. Итоги пересчитаны по строкам таблицы.

| # | Блок | Дни |
|---|---|---|
| 1 | RPC-сервис (RTK Query) для gpo, chain, gpmaster | 2-3 |
| 2 | Типы данных | 1 |
| 3 | Страницы: GPO (3-4), детали GPO (2), цепочки (3), мастер (2) | 10-11 |
| 4-5 | Навигация и маршруты | 2 |
| 6 | Таблицы (2), модальные окна (3), приоритеты и обвязка редактора (2) | 7 |
| 7 | Подключение существующего редактора | 5-8 |
| 9 | Тесты: unit (3), e2e (4) | 7 |
| | **Итого без переписывания редактора** | **34-39 (≈7-8 недель)** |
| 8 | Переписывание редактора на React/PatternFly (опционально) | 60-100 (3-5 месяцев) |

Допущения:
- Блок 7 занимает 5-8 дней только при наличии автономной сборки редактора (этап 4 DX-плана). Без неё +1 неделя на
  AMD-шимы.
- Оценка блока 8 исходит из объёма кода и тестов, которые придётся портировать. Прежние «2-3 недели» этот объём не учитывали.
- Недельный план исходного документа (5 недель) был короче суммы блоков; он не сохранён.

## 4. Решения

1. **Редактор GPUI не переписывать в MVP.** Он работает, покрыт тестами и изолирован RPC-контрактом. Решение о переписывании
   принимать по итогам пилота (одного экрана, например списка скриптов) и измерений: объём кода, время сборки, прохождение
   портированных тестов, клавиатурная доступность. Заявленное прежде «50-70% меньше кода» ничем не подтверждено.
2. **Targeting editor не переписывать** и не выделять в библиотеку, пока нет второго потребителя. Модуль небольшой,
   самодостаточный, и его drag-and-drop дублируется клавиатурным сценарием, который легко потерять.
3. **Бэкенд не трогать.** Нужные RPC-команды уже есть; контракт стоит зафиксировать общими JSON-примерами ответов
   (этап 3 DX-плана), чтобы pytest и фронтенд-тесты проверяли один формат.
4. **Работать в двух репозиториях** (`freeipa-server-gpo` и `freeipa-webui`) неизбежно: версию RPC (`API_VERSION`) и
   перечень команд нужно согласовывать при каждом релизе.

## 5. Риски

- Дублирование UI на переходный период и расхождение поведения двух интерфейсов.
- Редактор в iframe или модальном окне `freeipa-webui` потребует аутентификации сессии FreeIPA и общей политики CSP.
- Переписывание редактора заморозит развитие GPUI на месяцы либо приведёт к двум параллельным версиям.

## 6. Критерии готовности

MVP: CRUD для GPO, Chain и GPMaster; приоритеты; enable/disable цепочек; доступный редактор; базовые тесты.
Production: покрытие unit-тестов не ниже согласованного порога, e2e на ключевые сценарии, проверка доступности.

## 7. Первые шаги

1. Этапы 1-2 DX-плана (линтер, UI-тесты в CI).
2. Прототип блоков 1-2 и страницы GPO в `freeipa-webui` на реальном сервере из devcontainer.
3. Прототип подключения редактора после этапа 4.
