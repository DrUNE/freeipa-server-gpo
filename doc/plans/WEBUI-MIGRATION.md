# Предложение: управление GPO в freeipa-webui

**Статус:** предложение, не описание текущей системы. Заменяет `INTEGRATION-PLAN.md` и `GPO-EDITOR-ANALYSIS.md`
(остаются в истории git). Сначала нужен инструментарий из [FRONTEND-DX-PLAN.md](FRONTEND-DX-PLAN.md).
Факты сверены с этим репозиторием и с `freeipa-webui` 2026-10-18.

## 1. Что есть сейчас

| Слой | Состояние |
|---|---|
| Серверные команды | `gpo_*`, `chain_*` (включая `enable`/`disable`, `moveup_gpc`/`movedown_gpc`), `gpmaster_show`/`gpmaster_mod` (`add_chain`, `remove_chain`, `moveup_chain`, `movedown_chain`), около 30 команд `gpo_editor_*` |
| Страницы в штатном Web UI | `chain.js` (1193 строки) и `gpo.js` (395), jQuery-фасеты FreeIPA |
| Редактор GPUI | vanilla JS + AMD, около 20 тыс. строк, 22 layout'а preferences, targeting editor (~1650 строк, drag-and-drop с клавиатурной альтернативой), локали EN/RU, около 40 UI-тестов |
| Граница с libadmix | Только на сервере. Браузер видит типизированный RPC `gpo_editor_*` (`util/API.js`, ~29 методов) и не знает про SYSVOL |

Иерархия: GPMaster → Chain (упорядоченный) → GPO. При конфликте побеждает последняя политика.

## 2. Что предлагается

Три страницы в `freeipa-webui` (React + PatternFly + RTK Query): список/детали GPO, цепочки с приоритетами и
enable/disable, GPMaster (порядок цепочек, PDC Emulator). Редактор GPUI подключается как есть. Серверная часть не меняется.

Режимы сосуществования с текущим UI: временный двойной UI, затем замена (рекомендуется); iframe-прокси отвергнут как сложный.

## 3. Сверка с кодом freeipa-webui

Проверено по `../freeipa-webui` (ветка `main`, коммит `5dbf1030`).

**Подтверждено:** React 18, PatternFly 6, Redux Toolkit/RTK Query, вызовы через `api.injectEndpoints` в `src/services/rpc*.ts`,
по папке на сущность в `src/pages`, навигация в `navigation/NavRoutes.ts` и маршруты в `AppRoutes.tsx`, тесты vitest
(41 файл) и Cypress с cucumber-сценариями.

**Эталон объёма.** Самая простая сущность, HBAC-сервис, занимает: страницы 987 строк (список, таблица, вкладки, настройки),
модалки добавления и удаления 495, `rpcHBACServices.ts` 177, хук данных 117, утилиты 39, около 260 строк Cypress
(feature и steps) и правки общих файлов (`rpc.ts`, `globalDataTypes.ts`, `utils.tsx`, `NavRoutes.ts`, `AppRoutes.tsx`).
Это ≈2 тыс. строк на сущность без вложенных связей. У групп хостов один только Cypress занимает ≈1000 строк.

**Чего в исходном плане не было:**

| Находка | Следствие |
|---|---|
| В webui нет ни одного UI для упорядочивания (поиск `moveup`, `reorder`, `draggable`, `onDrag` по `src` пуст) | Порядок цепочек в GPMaster и GPO в цепочке (кнопки вверх/вниз) придётся проектировать с нуля |
| Переводы: типизированные ключи генерируются из серверного RPC `i18n_messages` (`npm run i18n:generate`) | Строки GPO сейчас в `js/locales/{en,ru}.js` плагина, а не в серверных сообщениях. Нужно решить, где они живут |
| Пункты меню зависят от `ConfigurationSettings` | Если плагин `freeipa-server-gpo` не установлен, раздел «Group Policy» должен скрываться (определение по доступным командам), иначе страницы отвечают ошибкой |
| Плагинная инфраструктура есть только в неслитой ветке `basic-plugin-infrastructure` (один коммит, одна точка расширения `dashboardContent`, плагины собираются вместе с ядром) | Она не позволяет добавлять страницы и пункты меню, значит нужны PR в ядро webui. Отдельный репозиторий-плагин пока невозможен |
| `ARCHITECTURE_SUMMARY.md` в webui требует «REST API endpoints» от сервера | Это неверно: страницам достаточно существующих JSON-RPC команд, серверную часть менять не нужно. Строку в webui стоит поправить |
| Линтер с `--max-warnings 820`, `knip` (неиспользуемые экспорты), prettier, подпись коммитов | Нужен запас на итерации ревью |

## 4. Объём и оценка

Рабочие дни, один разработчик. Оценка калибрована по эталону выше; предыдущая (34-39 дней) занижала цепочки и тесты.

| # | Блок | Дни |
|---|---|---|
| 1 | RPC-сервисы (gpo, chain, gpmaster) и типы | 3-4 |
| 2 | Сущность GPO: список, вкладки, добавление/переименование/удаление | 5-7 |
| 3 | Сущность Chain: список, вкладки, две группы (typeahead), список GPO с порядком, enable/disable | 7-9 |
| 4 | GPMaster: порядок цепочек, PDC Emulator (аналог страницы Configuration) | 3-4 |
| 5 | Навигация, маршруты, скрытие раздела без плагина, решение по переводам | 2-3 |
| 6 | Подключение существующего редактора | 5-8 |
| 7 | Тесты: vitest и Cypress для трёх сущностей | 8-10 |
| | Запас на ревью и линтеры (≈10%) | 3-5 |
| | **Итого без переписывания редактора** | **36-50 (≈8-10 недель)** |
| 8 | Переписывание редактора на React/PatternFly (опционально) | 60-100 (3-5 месяцев) |

Допущения:
- Блок 6 занимает 5-8 дней только при наличии автономной сборки редактора (этап 4 DX-плана). Без неё +1 неделя на
  AMD-шимы.
- Оценка блока 8 исходит из объёма кода и тестов, которые придётся портировать: ≈20 тыс. строк JS и около 40 UI-тестов.
- Cypress-тесты webui идут против живого FreeIPA, поэтому для блока 7 нужен стенд с установленным плагином (devcontainer
  этого репозитория подходит).

## 5. Решения

1. **Редактор GPUI не переписывать в MVP.** Он работает, покрыт тестами и изолирован RPC-контрактом. Решение о переписывании
   принимать по итогам пилота (одного экрана, например списка скриптов) и измерений: объём кода, время сборки, прохождение
   портированных тестов, клавиатурная доступность. Заявленное прежде «50-70% меньше кода» ничем не подтверждено.
2. **Targeting editor не переписывать** и не выделять в библиотеку, пока нет второго потребителя. Модуль небольшой,
   самодостаточный, и его drag-and-drop дублируется клавиатурным сценарием, который легко потерять.
3. **Бэкенд не трогать.** Нужные RPC-команды уже есть; контракт стоит зафиксировать общими JSON-примерами ответов
   (этап 3 DX-плана), чтобы pytest и фронтенд-тесты проверяли один формат.
4. **Принять заранее вопросы переводов и скрытия раздела** (см. раздел 3): они затрагивают оба репозитория.
5. **Переводы (рекомендация):** на время MVP держать строки новых страниц в локальном словаре EN/RU внутри webui; перенос в серверные `i18n_messages` делать отдельным шагом, когда плагин зарегистрирует сообщения. Решение подтвердить прототипом.
6. **Скрытие раздела (рекомендация):** первым PR в webui добавить определение доступности GPO-команд и пункт меню под этим условием, чтобы раздел не появлялся на серверах без плагина.
7. **Работать в двух репозиториях** (`freeipa-server-gpo` и `freeipa-webui`) неизбежно: версию RPC (`API_VERSION`) и
   перечень команд нужно согласовывать при каждом релизе.

## 6. Риски

- Плагинная инфраструктура webui не слита, поэтому изменения идут через общие файлы ядра (`NavRoutes.ts`, `AppRoutes.tsx`, `rpc.ts`) и могут конфликтовать с другими PR.
- Дублирование UI на переходный период и расхождение поведения двух интерфейсов.
- Редактор в iframe или модальном окне `freeipa-webui` потребует аутентификации сессии FreeIPA и общей политики CSP.
- Переписывание редактора заморозит развитие GPUI на месяцы либо приведёт к двум параллельным версиям.

## 7. Критерии готовности

MVP: CRUD для GPO, Chain и GPMaster; приоритеты; enable/disable цепочек; доступный редактор; базовые тесты.
Production: покрытие unit-тестов не ниже согласованного порога, e2e на ключевые сценарии, проверка доступности.
