# Предложение: управление GPO в freeipa-webui

[English](./WEBUI-MIGRATION.md) | **Русский**

**Статус:** предложение, не описание текущей системы. Нужный для этого инструментарий (ESM-исходники, тесты в CI, RPC-контракт
со сгенерированными типами — этапы 1-5 [FRONTEND-DX-PLAN.ru.md](FRONTEND-DX-PLAN.ru.md)) уже сделан. Работа над компонентами,
которая готовит редактор к переносу, описана в [COMPONENTS-PLAN.ru.md](COMPONENTS-PLAN.ru.md).
Факты сверены с этим репозиторием и с `freeipa-webui` 2026-10-21.

## 1. Что есть сейчас

| Слой | Состояние |
|---|---|
| Серверные команды | `gpo_*`, `chain_*` (включая `enable`/`disable`, `moveup_gpc`/`movedown_gpc`), `gpmaster_show`/`gpmaster_mod` (`add_chain`, `remove_chain`, `moveup_chain`, `movedown_chain`), 28 команд `gpo_editor_*` (плюс два алиаса совместимости) |
| Страницы в штатном Web UI | `frontend/public/chain.js` (1194 строки) и `gpo.js` (394), jQuery-фасеты FreeIPA; их действия покрыты юнит-тестами с подменами `freeipa/*` |
| Редактор GPUI | ES-модули в `frontend/src/` (≈19,9 тыс. строк без локалей, 4 модуля на TypeScript), один UMD/AMD-бандл `frontend/dist/js/app.js`, 22 layout'а preferences, targeting editor (≈3,1 тыс. строк в 6 файлах, drag-and-drop с клавиатурной альтернативой), EN/RU, 408 тестов фронтенда в 49 файлах |
| Код без DOM | ≈5,3 тыс. строк (≈27%): `core/{editor-dto,collection-value,targeting-tree-draft}.ts` и `util/API.ts`, модель и представления операндов таргетинга (`core/targeting/`), модели безопасности и аудита (`core/security/`, `core/advanced-audit/`), план зависимостей, layout'ы preferences (`core/preference-layouts/`); модель «всех политик» пока лежит в `templates/all-policies/` |
| Граница с libadmix | Только на сервере. Браузер видит типизированный RPC `gpo_editor_*` и не знает про SYSVOL |
| RPC-контракт | `tests/contracts/gpo_editor/*.json`: эталонный ответ каждой команды, сверяемый с настоящими командами (pytest), со стендом и с `API.ts` (vitest); из них генерируется `frontend/types/rpc.d.ts` |
| Точка входа редактора | `init({ containerId, policyName })` возвращает `{ container, cleanup }`; `cleanup()` снимает всё, что редактор поставил вне своего контейнера |
| Стили | Глобальные листы `frontend/src/styles/*.css` с токенами `--gpui-*` и CSS Modules; из 711 селекторов только 25 не ограничены областью редактора, в основном это drag-and-drop `chain.js` и окно `.modal-gpui` из `gpo.js` |

Иерархия: GPMaster → Chain (упорядоченный) → GPO. При конфликте побеждает политика с более высоким приоритетом (выше в списке; `moveup_gpc` и `moveup_chain` повышают приоритет).

## 2. Стратегия: три слоя

Редактор переносится по слоям, каждый по-своему:

| Слой | Объём | При переносе |
|---|---|---|
| RPC-контракт: эталоны, `rpc.d.ts`, `API.ts` | готов | переходит как есть; в webui становится `rpcGpoEditor.ts` поверх тех же типов |
| Код без DOM | ≈5,3 тыс. строк | выносится в пакет на TypeScript без фреймворка (`gpui-core`) и используется из React без изменений |
| Отрисовка (`ElementCreator`, `h()`) | ≈14 тыс. строк | заменяется на PatternFly экран за экраном; до этого весь редактор работает внутри webui «островом» |

Следствие для работы в этом репозитории: вкладываться в границы компонентов, крючки `data-*` и ARIA, вынос логики и истории как
спецификацию поведения ([COMPONENTS-PLAN.ru.md](COMPONENTS-PLAN.ru.md)), а не во внешний вид vanilla-отрисовки.

Сосуществование с текущим UI: временный двойной UI, затем замена (рекомендуется). iframe-прокси не нужен: webui раздаётся из
`/ipa/modern-ui`, с того же домена, что и `/ipa/ui`, поэтому бандл редактора можно загрузить напрямую в той же сессии.

## 3. Сверка с кодом freeipa-webui

Проверено по `../freeipa-webui` (ветка `feature/contrib`, коммит `b53ecb15`; `main` на `5dbf1030`).

**Подтверждено:** React 18, PatternFly 6, Redux Toolkit/RTK Query, вызовы через `api.injectEndpoints` в `src/services/rpc*.ts`,
по папке на сущность в `src/pages`, навигация в `navigation/NavRoutes.ts` и маршруты в `AppRoutes.tsx`, тесты vitest
(41 файл), Cypress с cucumber-сценариями (65 feature), базовый путь Vite `/ipa/modern-ui`.

**Эталон объёма.** Самая простая сущность, HBAC-сервис, занимает: страницы 987 строк (список, таблица, вкладки, настройки),
модалки добавления и удаления 495, `rpcHBACServices.ts` 177, хук данных 117, утилиты 39, около 260 строк Cypress
(feature и steps) и правки общих файлов (`rpc.ts`, `globalDataTypes.ts`, `utils.tsx`, `NavRoutes.ts`, `AppRoutes.tsx`).
Это ≈2 тыс. строк на сущность без вложенных связей. У групп хостов один только Cypress занимает ≈1000 строк.

**Что добавляет код freeipa-webui:**

| Находка | Следствие |
|---|---|
| В webui нет ни одного UI для упорядочивания (поиск `moveup`, `reorder`, `draggable`, `onDrag` по `src` пуст) и нет `@patternfly/react-drag-drop` | Порядку цепочек в GPMaster и GPO в цепочке нужен новый компонент `OrderableList` (кнопки вверх/вниз, перетаскивание с клавиатурной альтернативой); он же понадобится таргетингу |
| В webui нет Storybook | Истории этого репозитория — единственная спецификация компонентов; перенос Storybook в webui — естественный первый PR (см. этап 4) |
| Переводы: типизированные ключи генерируются из серверного RPC `i18n_messages` (`npm run i18n:generate`) | Строки GPO лежат в `frontend/src/locales/{en,ru}.js`, а не в серверных сообщениях. Нужно решить, где они живут |
| Пункты меню зависят от `ConfigurationSettings` | Если плагин `freeipa-server-gpo` не установлен, раздел «Group Policy» должен скрываться (определение по доступным командам), иначе страницы отвечают ошибкой |
| Плагинная инфраструктура есть только в неслитой ветке `basic-plugin-infrastructure` (один коммит, одна точка расширения `dashboardContent`, плагины собираются вместе с ядром) | Она не позволяет добавлять страницы и пункты меню, значит нужны PR в ядро webui. Отдельный репозиторий-плагин пока невозможен |
| `ARCHITECTURE_SUMMARY.md` в webui требует «REST API endpoints» от сервера | Это неверно: страницам достаточно существующих JSON-RPC команд, серверную часть менять не нужно. Строку в webui стоит поправить |
| Линтер с `--max-warnings 820`, `knip` (неиспользуемые экспорты), prettier, подпись коммитов | Нужен запас на итерации ревью |

## 4. Этапы и оценка

Рабочие дни, один разработчик. Оценка калибрована по эталону выше.

| # | Где | Этап | Дни |
|---|---|---|---|
| 0 | здесь | ◐ Вынести код без DOM в `frontend/src/core/` (TypeScript, строгий режим, без импортов из отрисовки); второй выход сборки — ES-модуль с `init` рядом с UMD-бандлом | 4-6 |
| 1 | webui | RPC-сервисы `rpcGpo.ts`, `rpcChain.ts`, `rpcGpmaster.ts`, `rpcGpoEditor.ts` (типы из `rpc.d.ts`); раздел показывается, только если доступны команды GPO; решение по переводам | 4-5 |
| 2 | webui | Страницы GPO, Chain, GPMaster: списки, вкладки, добавление/переименование/удаление, две группы цепочки (typeahead), enable/disable, PDC Emulator, `OrderableList` | 15-20 |
| 3 | webui | Редактор «островом»: компонент `<GpuiEditor policyName />` импортирует ES-модуль, вызывает `init()` в `useEffect` и возвращает `cleanup`; `chain.js` и `gpo.js` там больше не нужны | 3-5 |
| | webui | Тесты: vitest и Cypress для этапов 1-3; запас на ревью и линтеры (≈10%) | 10-14 |
| | | **Итого MVP (этапы 0-3)** | **36-50 (≈8-10 недель)** |
| 4 | webui | Пилот: один экран на React + PatternFly — «Расширенный аудит» (самый изолированный: 547 строк и готовая модель); Storybook в webui с историями используемых им компонентов. Измерить объём кода, доступность, время, перенос тестов; решить по этапу 5 | 5-8 |
| 5 | webui | Остальные экраны, от наименее к наиболее связанным: Скрипты → Безопасность → ADMX → формы элементов предпочтений → дерево и каталог → **таргетинг последним** | 40-70 |
| 6 | оба | Удалить vanilla-редактор, `chain.js`/`gpo.js` и AMD-дерево тестов | 3-5 |

Допущения:
- Этапы 0-3 сами по себе дают законченный результат: webui с полным редактором. Этапы 4-6 необязательны и могут растягиваться во времени.
- Этап 5 дешевле переписывания с нуля (ранее оценивалось в 60-100 дней), потому что код без DOM и контракт переиспользуются,
  а истории и интеграционные тесты описывают поведение, которое нужно сохранить; это всё равно самый крупный пункт.
- Cypress-тесты webui идут против живого FreeIPA, поэтому для тестов нужен стенд с установленным плагином (dev-контейнер этого
  репозитория подходит).

**Статус этапа 0 (выполнен частично).** `frontend/src/core/` есть (36 файлов TypeScript и `dto-types.d.ts`, ≈4,7 тыс. строк, все проверяются `tsc -p tsconfig.strict.json`): чистые модули перенесены туда, граница проверяется (ESLint `no-restricted-imports` для `.js` и `tests/unit/core-boundary.test.js` для всех файлов: только импорты `@gpui/core` и `@gpui/locales`, никаких браузерных глобалов). `npm run build:esm` собирает редактор как ES-модуль (`dist-esm/gpui.js` и `gpui.css`, не коммитится; `freeipa/ipa` и `freeipa/rpc` остаются голыми импортами, которые сопоставляет хост; `/img/...` в стилях разрешает хост), проверка — `tests/unit/esm-build.test.js`. Типы настоящие, но не полные: около 19 мест оставляют `any` (формы состояния правки операндов, таблицы представлений таргетинга, содержимое типизированных значений безопасности), у каждого есть комментарий; сгенерированный `rpc.d.ts` типизирует списки безопасности и аудита как `unknown[]`, поэтому формы их строк описаны вручную в `core/security/types.ts` и `core/advanced-audit/types.ts` и должны перейти в контракт сервера. Не сделано: `all-policies/model.js` и помощники представления (`preference/view/common.js`) пока вне `core`; `util/API.ts` остаётся в `util/` как транспорт (хост заменит его на `rpcGpoEditor.ts`).

## 5. Решения

1. **В MVP встраивать редактор как есть.** Он работает, покрыт тестами и изолирован RPC-контрактом. Заменять его экран за экраном
   только после пилота (этап 4) и его измерений. Объём кода измерять, а не предполагать его сокращение.
2. **Таргетинг последним.** Его функции вызывают друг друга по кругу, а drag-and-drop дублируется клавиатурным сценарием, который
   легко потерять. Не выделять его в библиотеку, пока нет второго потребителя; общая часть — `OrderableList`.
3. **Бэкенд не трогать.** Нужные RPC-команды есть; контракт закреплён эталонами, а новая команда без эталона роняет Python-тест.
4. **Где живёт `gpui-core`** (решить): в этом репозитории (публикуется пакетом или копируется в webui при сборке) или переезжает
   в webui. Пока webui его не использует, он остаётся здесь, в `frontend/src/core/`.
5. **Переводы (рекомендация):** на время MVP держать строки новых страниц в локальном словаре EN/RU внутри webui; перенос в
   серверные `i18n_messages` делать отдельным шагом, когда плагин зарегистрирует сообщения. Подтвердить прототипом.
6. **Скрытие раздела (рекомендация):** первым PR в webui добавить определение доступности команд GPO и пункт меню под этим
   условием, чтобы раздел не появлялся на серверах без плагина.
7. **Работать в двух репозиториях** (`freeipa-server-gpo` и `freeipa-webui`) неизбежно: версию RPC (`API_VERSION`) и перечень
   команд согласовывать при каждом релизе; эталонные ответы — общее определение.

## 6. Риски

- Плагинная инфраструктура webui не слита, поэтому изменения идут через общие файлы ядра (`NavRoutes.ts`, `AppRoutes.tsx`, `rpc.ts`) и могут конфликтовать с другими PR.
- Дублирование UI на переходный период и расхождение поведения двух интерфейсов.
- Формат бандла: сейчас это UMD/AMD для RequireJS FreeIPA; webui нужен выход в виде ES-модуля (этап 0). Зависимости `freeipa/ipa`
  и `freeipa/rpc` должен предоставить webui — небольшой адаптер поверх его RPC-клиента.
- Стили в обе стороны: листы редактора ограничены его областью (25 селекторов без ограничения относятся к страницам, которые webui
  заменяет), но базовые стили PatternFly (шрифты, `box-sizing`, элементы форм) действуют и внутри редактора. Проверить на «острове»
  на этапе 3; компоненты на CSS Modules подвержены этому меньше всего.
- Переписывание экранов замораживает их развитие на время работы над каждым; переписывание по одному экрану делает заморозку короткой.
- CI этого репозитория ещё не запускался на сервере Forgejo; эталонные снимки, возможно, придётся снять заново там.

## 7. Критерии готовности

MVP: CRUD для GPO, Chain и GPMaster; приоритеты; enable/disable цепочек; редактор доступен из webui; тесты vitest и Cypress для новых страниц.
Production: покрытие unit-тестов не ниже согласованного порога, e2e на ключевые сценарии, проверка доступности.
Каждый заменённый экран (этап 5): его истории проходят с теми же `play`-тестами, что и раньше, тесты контракта проходят, снимки просмотрены.

## 8. Первые шаги

1. Поправить в `freeipa-webui` строку про «REST API endpoints» в `ARCHITECTURE_SUMMARY.md`.
2. Этап 0 здесь: `frontend/src/core/` и выход сборки в виде ES-модуля.
3. Прототип этапов 1-2 (страница GPO) и «острова» (этап 3) в `freeipa-webui` на реальном сервере из dev-контейнера; по нему
   уточнить остальные оценки.
4. Параллельно — работа над компонентами по [COMPONENTS-PLAN.ru.md](COMPONENTS-PLAN.ru.md).
