# Выпуск RPM через CI

[English](./CI.md) | **Русский**

Весь конвейер описан в `.forgejo/workflows/python-backend.yml`:

1. Собирается один RPM для Sisyphus x86_64, включая `%check` и покрытие Python-кода.
2. Он сохраняется как `alt-packages`, а его SHA256 передаётся как выход задачи сборки.
3. Этот артефакт устанавливается в одноразовый домен FreeIPA и проходит живой набор тестов.
4. Только после успешной интеграции тот же артефакт публикуется, если это запрошено.

Перед установкой интеграционный тест проверяет контрольную сумму сборки. Публикация идёт в отдельной задаче: она проверяет ту же контрольную сумму, требует HTTP 201 от реестра ALT, скачивает опубликованный RPM и сравнивает байты по SHA256.
Между тестированием и публикацией второй сборки RPM нет.

Отдельная задача `frontend` (lint, форматирование, типы, проверка бандла, тесты фронтенда с покрытием) выполняется параллельно и описана в [frontend/README.md](../frontend/README.ru.md).

## Триггеры

| Событие | Сборка и юнит-тесты | Интеграция | Пакеты |
| --- | --- | --- | --- |
| Pull request | Да | Нет | Нет |
| Push в другую ветку | Да | Нет | Нет |
| Push в `master` или `ci/integration-container-probe` | Да | Да | Нет |
| Push подходящего тега `*-alt*` | Да | Да | Релизная группа |
| Ручной запуск, параметры по умолчанию | Да | Да | Нет |
| Ручной запуск, `publish_test_package=true` | Да | Да | Тестовая группа |

Теги релиза должны совпадать и с `Version-Release` из spec, и с версией и релизом собранного RPM. Существующие версии пакетов никогда не удаляются и не перезаписываются; ответ HTTP 409 завершает задачу публикации ошибкой. После неоднозначного сетевого сбоя или ошибки проверки скачанного файла проверьте реестр, прежде чем повторять публикацию: запрос PUT мог уже выполниться.

Токен пакетов передаётся только шагу публикации, через секрет `PACKAGE_TOKEN`. Интеграционной задаче этот секрет не нужен.
Привилегированная интеграция намеренно не включена для pull request.

## Проверка изменений

Запустите `python3 -m pytest tests/test_ci_publication.py`, чтобы проверить обработку сбоев публикации и защиту от пропуска интеграции. Эти тесты используют поддельные утилиты RPM и curl и никогда не загружают пакеты. Чтобы проверить настоящий конвейер сборки и домена, отправьте ветку CI. Чтобы проверить сам реестр, запустите этот workflow вручную с включённым параметром тестовой публикации и версией пакета, которой нет в этой группе.
Не создавайте тег релиза только для проверки CI.

CI задаёт `FREEIPA_GPO_REQUIRE_TESTS=1`: живой набор, в котором нет успешных тестов, есть пропущенные или ожидаемо упавшие (xfail), не может пройти шлюз релиза. Локально интеграционные тесты остаются необязательными.

## Ограничения

Прохождение этого шлюза сейчас доказывает серверный CRUD и публикацию в проверяемом окружении Sisyphus. Он не доказывает применение политик клиентом (`gpupdate`), доступность SMB, обновление со старых пакетов и полную матрицу прав RPC и ролей редактора. Большинство тестов редактора по-прежнему использует локальный root-доступ LDAPI и временные каталоги состояния. Эти проверки и усиление защиты раннеров и зависимостей остаются отдельной будущей работой.
